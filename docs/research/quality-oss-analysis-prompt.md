# Запрос для Gemini Deep Research: обзор рынка инструментов оценки качества

> целиком, начиная с «Проведи исследование».

---

Проведи исследование рынка open-source (и для сравнения — ведущих
коммерческих) инструментов, которые **оценивают качество сборки или релиза
ПО по результатам автотестов и смежных проверок** и принимают решение
«пропустить / остановить» (quality gate).

Мне нужно понять, какие подходы и идеи считаются сильными на рынке, чтобы
спроектировать собственный модуль оценки качества для фреймворка
автотестирования на Java. Код переносить не планирую — интересуют идеи,
модели данных, формулы и алгоритмы.

## Какие классы решений рассмотреть

Примеры — ориентиры, не ограничение. Добавь сильные проекты, которых нет в
списке, и объясни, почему они важны.

1. **Quality gates и «только новое»** — SonarQube/SonarCloud (Quality Gate,
   New Code, «Clean as You Code»), Codecov, Coveralls (patch coverage,
   flags, components), OpenSSF Scorecard, Lighthouse CI (budgets, assertions).
2. **Тестовая аналитика, flaky-тесты, триаж падений** — ReportPortal,
   Allure Report / Allure TestOps, Gradle Develocity, BuildPulse,
   Trunk Flaky Tests, Buildkite Test Engine, Datadog CI Visibility;
   научные подходы к flaky (DeFlaker, iDFlakies, FlakeFlagger и новее).
3. **Оценка по SLO и статистическое сравнение прогонов** — Keptn quality
   gates, Kayenta (canary analysis), Argo Rollouts Analysis, Iter8,
   пороги в k6 и Gatling.
4. **Эффективность самих тестов** — mutation testing (PIT, Stryker),
   покрытие кода и покрытие изменений (JaCoCo, diff-cover).
5. **Управление находками и принятием рисков** — DefectDojo,
   OWASP Dependency-Track, формат SARIF (baselineState, fingerprints).
6. **Scorecards и метрики доставки** — DORA, CHAOSS, Backstage
   Tech Insights / Scorecards, Sentry release health, OpenTelemetry
   semantic conventions для CI/CD.

## Что выяснить по каждому значимому решению

- Лицензия, модель (open-source / open-core / SaaS), активность проекта
  в 2025–2026, кто реально использует.
- **Единица оценки**: прогон, коммит, pull request, релиз, сервис?
- **Скоринг**: прозрачная формула или ML/эвристика? Можно ли пользователю
  настроить веса и пороги, как выглядит конфигурация?
- **Отделение нового от старого**: baseline, new code period, fingerprint
  находки, сравнение с N прошлыми прогонами. Как принимается риск
  (suppress / accept), есть ли срок действия принятия и аудит?
- **Нестабильные тесты**: как определяются, карантин, автоматический выход
  из карантина, влияние на гейт.
- **Классификация и группировка падений**: product bug / test bug /
  environment; правила (regex) против ML; что детерминировано.
- **Статистика**: какие методы сравнения (перцентили, median + MAD,
  Mann-Whitney, доверительные интервалы), минимальный размер выборки,
  как учитывают шум окружения.
- **Владение**: привязка проблем к компонентам, командам, сервисам.
- **Выходы**: отчёты, комментарий к PR, бейджи, дашборды, метрики
  (Prometheus/OpenMetrics), машиночитаемые форматы.
- **Слабые места**: на что жалуются пользователи (шум, ложные срабатывания,
  гейт начинают игнорировать, сложность настройки).

## Формат результата

1. **Карта рынка** — решения по классам, open-source отдельно от
   коммерческих, лидеры каждого класса.
2. **Сравнительная таблица** «решение × возможность»: гейт по новому,
   принятие риска со сроком, flaky/карантин, классификация падений,
   статистическое сравнение, настраиваемые пороги, эффективность тестов,
   владение, форматы экспорта.
3. **Топ-15 идей, которые стоит взять**, для каждой: источник (со ссылкой),
   суть, какую проблему решает, насколько прозрачна и воспроизводима,
   требует ли сервера/базы данных или работает на файлах в CI, сложность
   реализации (S/M/L).
4. **Антипаттерны** — подходы, которые на практике не работают, с
   примерами и причинами.
5. **Тренды 2025–2026** — куда движется рынок (AI-триаж, test impact
   analysis, flaky-менеджмент, policy-as-code и т. п.).
6. **Рекомендации** для небольшого open-source фреймворка автотестирования,
   который работает в CI без собственного сервера и хочет прозрачные,
   объяснимые оценки.
